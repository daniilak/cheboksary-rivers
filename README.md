# Реки Чебоксар · вода и город

Интерактивная 3D-карта реальных геоданных и **сценарная лаборатория**, работающая без API-ключей. Основной режим показывает здания OSM, связанное с Волгой затопление и двумерный расчёт течения Волги. Одномерные сечения служат отдельной диагностикой. Отдельный режим сохраняет прежний качественный эскиз размыва.

## Запуск

```sh
python3 -m http.server 8767 --bind 127.0.0.1 --directory dist
```

Откройте http://127.0.0.1:8767/.

1. Выберите «Исходный», «Половодье» или «Подъём +3 м». Уровень и расход можно изменять независимо.
2. ▶ проигрывает 120 дней условного половодья; ползунок дня позволяет сравнить подъём, пик и спад.
3. «Показывать здания» меняет отображение; «Здания как препятствия» меняет расчёт. Это разные переключатели.
4. «Приблизить здания у воды» показывает первый контур рядом с затоплением, либо низко расположенный контур в исходном сценарии. Нажатие на дом открывает его исходный объект OSM, высоту и результат скрининга.
5. «2D-течение Волги» рассчитывает час переходного потока из состояния покоя: объём, две компоненты импульса, трение и непроницаемые берега. На карте отображается рассчитанное поле. При изменении параметров оно пересчитывается; во время проигрывания дней временно показывается 1D-оценка.
6. «Сечения Волги» показывает поперечники. В панели меняются сечение, предполагаемая глубина и шероховатость; показаны скорость, площадь, число Фруда и уклон потерь.
7. GeoJSON сохраняет параметры, ячейки затопления, контуры у воды и сечения с расчётными величинами, а после расчёта 2D — векторы скорости, уровни и диагностику баланса. Координаты геометрии — WGS84; высоты — в системе DSM EGM2008.

## Что реализовано

- 24 326 контуров зданий из реальной региональной выгрузки OSM, включая внутренние дворы, ID, адреса и происхождение высоты. Сетка DEM разрешает 7 516 контуров по наличию центра ячейки внутри них; остальные дома видны и участвуют в предварительном анализе соседства с водой.
- Горизонтальная поверхность Волги вместо поверхности, повторяющей шум DEM. Отдельный ноль сценария — 61,5 м EGM2008, медиана DSM в водном полигоне.
- Затопление распространяется от Волги через четыре соседние ячейки ниже уровня; изолированные низины не заливаются. Здания могут быть непроницаемыми препятствиями. Это равновесный расчёт связности, а не расчёт волны во времени.
- 85 сечений по OSM; средняя скорость `v = Q / (B × h)`, число Фруда и уклон потерь по Маннингу. Глубина **задана**, а не измерена. Стрелки Волги ускорены ×600 и ограничены водным полигоном.
- Двумерные уравнения мелкой воды на постоянной OSM-маске Волги, сетка около 103 × 124 м. Конечные объёмы, поток Русанова, гидростатическая реконструкция, ограничение CFL и трение Маннинга. Запад: заданный расход; восток: заданный уровень. Плоское дно условно; это переходный сценарий, а не откалиброванное течение.
- Условный гидрограф: рост до дня 35, затем спад к дню 120. Расход 2 500–10 000 м³/с, подъём в пик по умолчанию 0,3 м. Это не наблюдённое половодье конкретного года.
- Теги подземных/закрытых участков OSM сохранены; такие участки не изображаются открытой рекой.

## Граница применимости

Это проверяемая учебная и исследовательская модель на открытых данных, **не откалиброванный прогноз затопления**. Нет промеров дна, высокоточного DTM, согласования DSM с высотной системой гидропоста, водосбросов ГЭС, водопропускных сооружений, ледовых явлений, ливневой канализации, стока притоков и валидации 2D-расчёта по наблюдениям. 2D-решатель работает только внутри исходного водного полигона с неподвижными берегами; затопление суши рассчитывается отдельным равновесным методом. Здания влияют на этот расчёт затопления, а не на русловую 2D-сетку. Погрешность DSM может превосходить сезонный подъём воды. Оранжевый дом означает затопленную соседнюю ячейку, а не воду внутри здания. Отсутствие контакта не означает отсутствие реального риска.

Часть зданий и растительности уже включена в DSM; контуры не используются для «очистки» DSM от крыш. Их высота в 3D не прибавляется к гидравлической поверхности: расчётный учёт зданий — маска непроницаемых ячеек. Пропуск воды между домами на расстояниях меньше шага DEM недостоверен.

Полное описание алгоритмов, данных, допущений и пути к инженерной модели: [SOURCES.md](SOURCES.md).

## Проверка

```sh
node --check dist/app.js
node --check dist/hydrology-view.js
node scripts/check-hydrology.mjs
node scripts/check-scene.mjs
node scripts/check-shallow-water.mjs
```

Гидрологические проверки включают замкнутую низину, стену и открытие прохода, отсутствие диагонального перетекания, сохранность исходного DEM, непрерывность расхода, чувствительность формулы Маннинга, гидрограф и реальные данные. Для 2D отдельно проверяются покой над неровным дном, прорыв воды на сухую поверхность, положительность глубины, симметрия, отражающая стенка, постоянный сквозной поток и баланс открытых границ. Выполняются часовые расчёты на OSM-геометрии Волги при трёх сочетаниях глубины, расхода и уровня. Проверки прежнего режима контролируют конечность преобразований, размыв/отложения и точную перемотку.

## Пересборка данных

Python 3 с `osmium`, `numpy`, `rasterio`, `shapely`; проверенные версии закреплены в `requirements-data.txt`. Оригинальный PBF сохранён локально в `raw/RU-CU-2026-10-02.pbf` (в Git и на сайт не попадает).

```sh
python scripts/extract_osm.py /path/to/RU-CU.pbf /tmp/cheb-water.json
python scripts/prepare_data.py /path/to/DEM.tif /path/to/boundary.json /tmp/cheb-water.json
python scripts/prepare_hydrology.py /path/to/RU-CU.pbf
```

Последний шаг необходим: добавляет здания, маски, сечения, метаданные и теги сегментов рек. Он работает с тем же OSM PBF, что и первые шаги. Проверки ловят рассогласование тегов и сегментов.

## Публикация

Существующий сайт: https://daniilak.github.io/cheboksary-rivers/.

При push в `main` `.github/workflows/pages.yml` запускает проверки и публикует `dist`. Изменения в локальном рабочем каталоге сами по себе опубликованный сайт не обновляют. Исходные загрузки `raw/` не публикуются; производные геоданные и Three.js включены в `dist`. Внешние шрифты и сервисы для работы карты не требуются.
